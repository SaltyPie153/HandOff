HANDOFF · 제품 명세 v1.3 쉽게 읽기

우리 팀의 약속을
잊지 않는 공책.

“이거 전달했어?” “어느 내용에 동의했지?”
개발팀 4~5명이 주고받는 인수인계와 개발 약속을 한곳에 기록합니다.

문서에 적힌 목표 동작을 설명합니다

01. 공책에 쓰는 건 두 가지

📦

인수인계 = 바통 전달

“여기까지 했어. 다음에 이걸 살펴봐 줘.”

받는 사람이 내용 확인을 하면 확인 완료.

내용을 확인했다는 뜻이지, 다음 개발까지 끝냈다는 뜻은 아닙니다.

🤝

개발 계약 = 함께 지킬 약속

예: “이 기능은 이 방식으로 연결하자.”

보낸 사람 + 받는 사람 + 필수 PM이 모두 같은 버전에 동의해야 확정.

PM은 선택 사항입니다. 참조로 참여한 PM은 동의가 필수가 아닙니다.

02. 이렇게 주고받아요

🧑‍💻

A의 Codex

내용을 작성하고
허가된 프로젝트로 전송

→
📬

HandOff

요청과 버전을 저장하고
서버에서 근거 확인

→
👤

B의 웹 화면

직접 내용을 확인하거나
동의·수정 요청

MCP는 여기서 Codex와 HandOff를 이어 주는 연결 통로입니다. 프로젝트별 권한을 주면 매번 전송 버튼을 누를 필요가 없습니다.

최신 근거가 명확하면

서버 Codex가 사실을 회신

B의 PC가 꺼져 있어도, 허용된 계약 자료에 적힌 사실을 팀에 공개합니다.

근거가 없거나 서로 다르면

B에게 비공개 검토로 전달

추측을 자동 게시하지 않습니다. B가 웹에서 검토·수정하고 공개합니다.

AI가 답해도, 사람의 확인·동의는 따로.자동 전송·자동 회신·자료 조회는 사람의 승인 기록을 만들지 않습니다.

03. 봉투 겉면과 속지는 달라요

📢

프로젝트 팀이 보는 것

전송된 요청의 제목
이미 공개한 회신

공통 공간은 팀이 함께 보는 게시판입니다.

🔒

당사자가 보는 것

요청 본문·첨부·비공개 버전
전송 전 초안은 작성자만

미게시 자동 검토 결과는 수신자 B만 봅니다. 계약 제안은 지정된 PM도 참여 권한에 따라 봅니다.

로그인 → 가입 승인 → 프로젝트 배정 → 공통 공간 → 내 공간.
로그인했다고 모든 프로젝트가 열리지는 않습니다. 승인 회원이 직접 만든 프로젝트에서는 그 회원이 관리 담당자가 됩니다.

04. 새 약속을 논의해도, 옛 약속은 유효해요

지금 지켜야 하는 약속확정본 v1새 합의 전까지 유지
＋
아직 논의 중인 약속변경안 v2필수 참여자가 다시 동의

보낸 내용은 고치지 않아요

수정할 때는 새 버전을 보냅니다.
옛 동의는 새 버전으로 따라가지 않습니다.

내 응답과 전체 완료도 달라요

내가 동의했어도 필수 PM이 기다리는 중이면
전체 계약은 아직 확정되지 않습니다.

수정 요청이 나오면 그 버전의 추가 응답을 닫고 새 버전을 기다립니다. 계약을 폐기할 때도 별도 합의가 필요합니다.

05. 웹은 기록장, Discord는 알림벨

🌐

웹에서 확인하고 동의

본문·첨부·버전·이력을 보고
사람이 확인·동의·수정 요청을 합니다.

🔔

Discord로 도착 알림

제목·대상·상태·버전과 웹 링크를 받습니다.
알림 실패가 웹 기록을 취소하지 않습니다.

조금 더 궁금하면

첫 버전에 들어가는 것 / 빠지는 것

포함: 로그인·가입 승인, 프로젝트, 받은함·보낸함·초안, 첨부, 버전별 확인·동의, MCP 자동 전송, 근거 기반 회신, Discord 알림.

제외: 일반 채팅, 전체 업무 관리, 결제·요금제, AI의 임의 코드 수정·PR 생성, 코드가 계약을 지켰는지 자동 판정.

담당자가 떠나거나 전송이 꼬이면?
  • 필수 담당자가 접근 권한을 잃으면 미완료 요청을 멈춥니다. 관리 종료 후 새 담당자의 연결 요청으로 이어가며 옛 동의를 넘기지 않습니다.
  • 전송 재시도는 같은 요청을 중복 생성하지 않도록 처리합니다. 오래된 버전에 대한 응답은 막습니다.
  • 이미 확정된 계약은 담당자가 떠났다는 이유만으로 사라지지 않습니다.
기술과 운영은 어떻게 정했나요?

화면은 React·TypeScript, 서버는 NestJS·TypeScript, 데이터는 PostgreSQL·Prisma를 사용하도록 정했습니다.

운영은 GCP 서울 VM 한 대에서 Docker Compose로 실행하는 설계입니다. DB와 첨부를 하루 1회 백업해 7일 보관하고, 실제 복구도 검증해야 합니다.

확정된 요구와 제안, 아직 확인할 일

합의된 요구: 당사자 전용 본문, 팀 공개 제목·회신, 프로젝트별 허가에 따른 자동 전송, 명시된 근거 기반 회신, 사람의 별도 확인·동의.

명세의 검토 대상 제안: 공통 공간·내 공간이라는 명칭, 전송본 고정과 새 버전 발행, 기존 확정본 유지 등 세부 동작.

미확인: 실제 구현·배포 완료 여부는 이 요약에서 확인하지 않았습니다. 명세 자체도 Codex 연결·인증·Discord 설치 권한의 기술 검증이 필요하다고 명시합니다.
