# 인증 기능 검증 안내

## 선행 조건

1. 앱 기본 골격을 develop에 통합하고 Node 24, PostgreSQL 개발/시험 환경을 준비한다.
2. 개발·시험 환경에 Google와 Discord의 별도 OAuth 앱, 정확한 callback URI와 비밀 설정을 제공한다. 저장소에 비밀값을 기록하지 않는다.
3. 실제 최초 관리자로 사용할 계정으로 한 번 로그인해 대기 회원 ID를 얻는다. 운영자만 명시적 초기 관리자 명령으로 그 ID를 지정한다.

## 자동 검증

- 정책 단위 테스트: 신규·재로그인·이메일 중복·연결 충돌·대기 차단·관리자 권한·중복 승인.
- DB 통합 테스트: 제공자 계정 동시 가입, 승인/감사 기록 원자성, 세션 만료·로그아웃, 재시도.
- API 계약 테스트: 로그인 상태별 401/403/409/정상 응답, CSRF·state 위조, 비밀값 비노출.
- 웹 검증: 로그인→대기→관리자 승인→프로젝트 진입, 제공자 연결 전·후 같은 회원 ID.
- 실제 제공자 시험: Google와 Discord 각각 시험 계정으로 callback과 연결을 별도로 점검한다.

## 완료 판정

R20·R23·R24의 이 기능 범위를 입증해야 한다. 프로젝트 목록·본문·첨부와 Discord 알림은 후속 기능의 검증 대상이므로, 인증 경계만 통과했다고 전체 제품 기준을 완료 처리하지 않는다. 실제 제공자 자격 증명이 없으면 자동 검증과 실연동 미검증을 구분해 기록한다.
