# 사람의 인수인계 처리 확인

## 준비

- Node.js 24, Docker PostgreSQL과 승인된 프로젝트 멤버 A·B·C를 준비한다.
- 저장소 루트에서 `npm ci`, `npm run build`, `npm run db:up`, `npm run db:migrate`를 실행한다. 기존 DB에는 먼저 백업을 확보한다.
- `npm run dev:api`, `npm run dev:web`로 실행하고 `.env`의 실제 웹 포트로 접속한다. 기존 다른 체크아웃의 실행 포트와 겹치지 않게 한다.
- A의 MCP 연결은 [MCP Quickstart](../004-mcp-handoff/quickstart.md)를 따른다. 변경된 `resend_request`를 사용하려면 MCP 빌드와 연결 재시작이 필요하다.
- B·C는 서로 다른 브라우저 세션을 사용한다. 사람 처리 자체에는 외부 모델 API 키가 필요하지 않다.

## A 요청 → B 수정 요청 → A 재전송 → B 확인

1. A의 MCP `send_request`로 B에게 공개 제목과 비공개 본문을 전송한다. 반환된 요청 ID를 보관한다.
2. B의 프로젝트 **받은함**에서 버전 1을 연다. **비공개 수정 의견**을 입력하고 **수정 요청**을 누른다.
3. A의 **보낸함**에는 **수정 필요 1**과 수정 요청 알림이 표시된다. 요청 상세에서 B의 의견을 확인한다. 알림을 읽어도 요청 처리 상태는 바뀌지 않는다.
4. C의 팀 피드에서는 공개 제목과 게시된 공개 회신만 보인다. B의 수정 의견·요청 본문·버전별 처리 기록과 직접 상세 주소 접근은 차단된다.
5. A의 MCP `get_my_request`로 현재 버전을 확인한 뒤 `resend_request`를 실행한다.

   ```json
   {
     "requestId": "요청 UUID",
     "expectedVersion": 1,
     "privateBody": "수정한 비공개 본문",
     "idempotencyKey": "새 UUID"
   }
   ```

   자동 사실 확인이 필요한 경우에만 명시된 근거와 일치하는 `verificationClaim`을 추가한다. 같은 전송의 재시도는 내용과 키를 그대로 사용한다. 새 편집·새 전송은 새 키를 사용한다.
6. 같은 요청의 버전 2가 생성되고 B에게 새 버전 알림·확인 필요 건수가 생긴다. 제목과 당사자는 바뀌지 않는다.
7. B가 최신 본문을 검토하고 **내용 확인 완료**를 누르면 A에게 알림이 생긴다. 이는 해당 버전의 내용 확인이며 개발 완료나 계약 동의가 아니다.
8. 새로고침 후 상태·이력·읽음이 유지되는지 확인한다. 과거 버전 선택 시 원래 본문과 수정 의견을 읽을 수 있지만 새 응답을 저장할 수 없다. 확인된 버전 다음에 새 버전이 오면 다시 검토해야 한다.

## 오류·권한·경합

- 오래된 탭에서 응답하면 HTTP 409로 거부된다. **최신 버전 새로고침**으로 내용을 다시 확인한다. 작성 중인 수정 의견은 화면 내 버전 갱신에서 보존되며 자동 제출되지 않는다. 브라우저 전체 새로고침·종료를 견디는 초안 저장은 제공하지 않는다.
- 같은 키 재시도는 응답·버전·알림을 늘리지 않는다. 같은 키를 다른 내용에 재사용하면 409다.
- A·C·프로젝트 관리자·MCP 토큰은 B의 사람 확인을 대신할 수 없다. 멤버 제외·승인 상실 뒤에는 처리·알림 접근이 차단된다. 상대가 접근 권한을 잃은 요청은 실행 가능한 할 일 집계에서 제외된다.
- 팀 공개 회신은 사람 확인과 별도다. 자동 작업은 실행한 버전에만 게시하며, 새 버전 도착·사람 응답 뒤 늦게 도착한 결과는 게시하지 않는다.

## 자동 검증

루트에서 `npm run build`, `npm run typecheck`, `npm test`, `npm run test:integration`, `npm run test:e2e`를 실행한다. 실제 작업 셸에서는 프로젝트 지침에 따라 `rtk proxy`를 앞에 붙인다.

통합/E2E 실행기는 별도 시험 DB와 세션을 사용한다. 마이그레이션은 기존 회신·작업을 버전 1에 연결하고 사람 확인 이력을 새로 만들어내지 않는다. 연결이 모호한 기존 데이터는 이전을 중단한다.

이번 자동 검증에는 실제 Google·Discord OAuth, Solar API 호출, 운영 배포·백업 복구가 포함되지 않는다. 계약·PM 동의, 첨부, Discord 알림, 담당자 변경·관리 종료는 후속 범위다. `.env`, MCP 토큰, API 키는 Git이나 공유 결과에 포함하지 않는다.
