# 프로젝트 룸과 멤버 권한 확인

## 준비

- Node.js `>=24.15 <25`, npm 10.9.2, Docker Desktop의 Linux engine을 준비한다.
- 저장소 루트에서 `npm ci`, `npm run db:up`, `npm run db:migrate`, `npm run dev:api`, `npm run dev:web`을 실행한다. 기존 개발 DB의 볼륨은 초기화하지 않는다.
- API와 웹은 각각 로컬 프로세스로 실행한다. 기본 웹 주소는 `http://127.0.0.1:5173`이다.
- 실제 가입 흐름에는 `.env`의 Google·Discord OAuth 설정과 서로 다른 시험 계정이 필요하다. 자격 증명은 화면 캡처·로그·커밋에 포함하지 않는다.

## 두 계정 수동 확인

1. 승인된 회원 A로 로그인해 `/projects`에서 프로젝트를 만든다. 새 프로젝트가 목록에 나타나고 룸에서 A가 관리 담당자로 표시되는지 확인한다.
2. 승인 대기 회원은 `/projects`와 직접 룸 주소로 들어갈 수 없는지 확인한다.
3. 승인된 회원 B로 로그인해 처음에는 A의 프로젝트가 목록에 없고 직접 주소도 거부되는지 확인한다.
4. A의 룸에서 **멤버 관리**를 열고 B를 검색·추가한다. B의 프로젝트 목록을 새로고침하고 같은 룸 및 멤버 현황을 확인한다.
5. 미배정 서비스 관리자로 `/admin/projects`를 열어 멤버 관리가 가능한지 확인한다. 같은 프로젝트 룸 직접 주소는 거부되어야 한다.
6. A가 B를 제외한다. B의 열린 화면을 새로고침하면 프로젝트가 목록에서 사라지고 직접 룸 주소도 거부되어야 한다.
7. B에 Google·Discord를 연결했다면 두 수단으로 각각 로그인해 같은 프로젝트 배정이 보이는지 확인한다. 이 시험은 실제 OAuth 계정이 준비된 경우에만 완료로 기록한다.

## 자동 검증

`npm run test:integration`은 빈 격리 PostgreSQL에 마이그레이션을 적용한 뒤 프로젝트 생성·권한·감사 기록을 검사한다. `npm run test:e2e -- tests/e2e/projects.spec.ts`는 두 회원과 서비스 관리자, 승인 대기 회원을 격리 DB에 생성해 브라우저 흐름을 확인한다. `pwsh -NoProfile -File scripts/check-product.ps1`은 빌드·타입·단위·통합·전체 E2E를 순서대로 실행한다. 시험 데이터와 볼륨은 시험 실행기가 자신이 만든 것만 정리한다.

이번 룸에는 프로젝트 정보·멤버 현황·빈 요청 안내만 있다. 인수인계·계약 본문, 첨부, 버전 합의는 후속 기능이다.
