# MCP 요청 연결

1. Node.js 24에서 루트 `npm ci`와 `npm run build`를 실행한다.
2. 승인된 프로젝트의 `/settings`에서 프로젝트별 MCP 연결을 발급한다. 토큰은 발급 시 한 번만 표시된다.
3. Codex의 MCP 설정에서 stdio 명령을 `node <저장소 절대경로>/apps/mcp/dist/src/index.js`로 지정한다. 해당 프로세스 환경에 `HANDOFF_API_ORIGIN`(개발: `http://127.0.0.1:3000`)과 `HANDOFF_MCP_TOKEN`을 설정한다. 토큰을 설정 파일이나 저장소에 평문으로 커밋하지 않는다.
4. Codex에서 `list_my_projects`로 프로젝트 범위를 확인한다. `send_request`는 수신자 ID, 팀 공개 제목, 당사자 전용 본문, 재시도에 재사용할 `idempotencyKey`를 요구한다. `get_my_request`는 본인이 당사자인 요청만 읽는다.
5. 연결을 끊으려면 웹 설정에서 해당 MCP 연결을 철회한다. 프로젝트에서 제외되거나 가입 승인이 취소돼도 서버가 다음 호출을 차단한다.

MCP 도구에는 사람의 인수인계 확인 완료나 계약 동의 기능이 없다. 토큰과 요청 비공개 본문을 채팅, 로그, Git에 올리지 않는다.

## 자동 회신 근거

- 서버의 비공개 로컬 스냅샷 암호화를 위해 `HANDOFF_EVIDENCE_KEY` 환경 변수에 임의 32바이트 키의 64자리 16진수 값을 설정한다. 키가 없으면 로컬 동기화가 거부된다. 키는 `.env` 등 Git 제외 설정에만 보관한다.
- `/settings`에서 수신자 본인의 프로젝트와 허용할 로컬 텍스트 계약 파일의 절대 경로를 등록한다. 등록 시 한 번 표시되는 별도의 `HANDOFF_SYNC_TOKEN`을 로컬 커넥터 프로세스 환경에 설정한다. `node scripts/sync-evidence.mjs --file <등록한 절대 경로> --source-id <등록된 근거 ID> --watch`로 시작하면 시작 시점과 이후 한 시간마다 지정 파일만 동기화한다. PC가 꺼져 있거나 마지막 성공 동기화가 24시간을 넘으면 자동 근거에서 제외된다. 업로드 실패 전에 변경 보고가 성공한 경우에도 근거가 낡은 것으로 처리된다.
- GitHub 파일은 `/settings`에서 소유자·저장소·파일 경로·브랜치/커밋을 지정한다. 서버는 매번 커밋 SHA를 확인하고 그 SHA의 파일을 읽는다. 비공개 저장소에는 서버 환경의 읽기 전용 `GITHUB_READ_TOKEN`이 필요하다. 토큰을 브라우저에 입력하지 않는다.
- 요청의 `verificationClaim`은 근거 파일에 독립된 한 줄로 명시된 문구만 입력한다. 이 값이 없거나 근거가 오래됐거나 서로 충돌하면 자동 공개 회신을 만들지 않고 수신자에게 웹 검토를 요청한다.
- 근거 지정을 해제하면 현재 스냅샷 본문을 삭제하고 이후 판정에서 제외한다. 이미 게시된 회신과 백업 보관 기간은 별도로 유지된다.

현재 제품에는 확정된 개발 계약을 생성·동의·폐기하는 데이터 모델이 없다. 이 근거 종류는 실제 확정 계약 기능이 구현되기 전까지 자동 판정에 사용하지 않는다.
