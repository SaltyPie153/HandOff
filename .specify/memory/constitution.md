# HandOff Constitution

## Core Principles

### I. 명세가 구현의 기준이다

- 기능 구현 전에 범위, 사용자 흐름, 권한, 상태 전이, 실패 상황과 검증 가능한 수용 조건을 명세한다.
- 기능 명세 → 구현 계획 → 작업 분해 → 구현 → 검증 순서를 따른다.
- 각 구현 작업과 검증 결과는 관련 수용 조건에 연결한다. 동작 변경은 명세에 먼저 반영한다.
- 제품 전체의 동작 기준은 `docs/product/spec.md`, 기술 결정은
  `docs/product/technical-design.md`에서 관리한다. 기능 명세는 이를 구체화하고 원본을 복제하지 않는다.
- 구현을 막는 미결정 사항은 질문하거나 기술 검증으로 해소한다. 추정을 확정 사실로 기록하지 않는다.

근거: 문서와 코드가 서로 다른 약속을 갖지 않도록 한다.

### II. 사람의 승인과 에이전트 활동을 구분한다

- 최종 전송과 버전별 확인·동의는 권한 있는 사람이 명시적으로 수행한다.
- Codex는 검증된 권한 범위에서 초안 작성과 조회를 지원하며 사람의 전송·동의를 대행하지 않는다.
- 일반 인수인계의 수신·검토 확인을 개발 완료나 개발 계약 합의로 표시하지 않는다.
- 개발 계약의 필수 확인자와 참조자를 구분하고, 참조자의 열람을 합의 조건으로 사용하지 않는다.
- 에이전트 조회 기록은 특정 버전 조회 사실만 나타낸다. 이해·구현·승인 완료를 추론하지 않는다.

### III. 권한 경계를 서버에서 강제한다

- 로그인, 서비스 가입 승인, 프로젝트 배정은 별개로 검사한다.
- 모든 API와 첨부 접근에서 사용자·프로젝트·행위 권한을 서버가 검증한다.
- 전송된 기록은 해당 프로젝트 멤버에게 공개하고, 미전송 초안은 작성자에게만 공개한다.
- 서비스·프로젝트 관리자 권한만으로 타인의 초안 열람이나 응답 대행을 허용하지 않는다.
- 로그인 제공자 연결은 로그인한 사용자의 명시적 인증으로 처리한다. 이메일 일치로 자동 병합하지 않는다.
- 권한 상실은 이후 접근과 응답에 반영하되, 기존 합의와 활동 이력을 임의로 삭제하지 않는다.

### IV. 버전과 합의 상태의 정합성을 보존한다

- 전송한 본문·첨부·참여자 구성은 불변이다. 변경은 새 버전으로 만들고 이전 동의를 승계하지 않는다.
- 검토 중인 변경안과 현재 유효 계약을 구분한다. 미확정 변경안은 기존 확정본을 덮어쓰지 않는다.
- 개인의 처리 완료와 전체 요청의 합의 완료를 별도로 계산한다.
- 권한·최신 버전·현재 상태·기존 응답·기준 확정본 검증과 상태 저장은 원자적으로 처리한다.
- 중복 전송과 응답 재시도는 같은 결과로 수렴해야 하며 요청·응답·알림 이벤트를 중복 생성하지 않는다.
- 철회·수정 요청·최종 동의 등 경합은 명세의 상태 전이 규칙으로 판정하고 종료 상태를 다시 열지 않는다.
- 누가 어떤 버전에 어떤 행동을 했는지 추적 가능한 이력을 남긴다.

### V. 서비스 기록을 원본으로 유지한다

- 실제 인수인계·계약·회신 기록은 서비스 데이터로 관리한다. 제품 사용 기록을 코드 저장소에 누적하지 않는다.
- Discord는 알림 창구다. Discord 메시지나 알림 성공 여부를 계약 확정의 근거로 사용하지 않는다.
- 상태 변경과 알림 이벤트 생성은 함께 저장하고 외부 발송은 별도로 재시도한다.
- 외부 알림 장애가 저장된 요청·응답을 취소하거나 웹 받은함 이용을 막아서는 안 된다.
- 외부 전달 결과가 불명확하면 이를 표시한다. 외부 시스템까지 정확히 한 번 전달된다고 단정하지 않는다.

### VI. 완료는 검증 근거로 판단한다

- 권한, 버전별 합의, 상태 경합, 중복 처리, 알림 재시도에는 자동 검증을 마련한다.
- 핵심 규칙은 정상 흐름뿐 아니라 거부·실패·동시 실행 시나리오를 검증한다.
- 프로젝트 선택부터 양방향 회신까지는 두 사용자 계정으로 통합 검증한다.
  Discord 연동 구현 시 시험 채널을 포함한다.
- 각 기능은 해당 수용 조건의 검증 결과가 있어야 완료로 처리한다.
  실행한 명령·결과·미검증 범위를 기록하고 실패한 검증을 숨기지 않는다.
- Harness 검사 통과를 제품 테스트 통과로 간주하지 않는다.
  구현하지 않은 연동이나 배포를 작동하는 것으로 보고하지 않는다.
- 가역적인 단순 문서 변경에 구현을 그대로 따라 하는 테스트를 추가하지 않는다.
  변경 위험에 맞는 검증을 수행한다.

### VII. 작은 팀에서 검증하고 단순하게 운영한다

- 초기 범위는 내부 4~5명 팀의 인수인계와 계약 확인이다. 실제 사용 문제를 근거로 확장한다.
- 결제·복잡한 승인 편집기·자동 담당자 추천 등 범위 밖 기능을 선행 구현하지 않는다.
- 새로운 서비스·인프라·추상화는 현재 요구와 운영 비용에 대한 근거를 계획에 기록한다.
- 데이터 영속성과 복구 가능성을 비용 절감보다 우선한다.
- 운영 전 별도 환경에서 DB와 첨부를 복구하고 참조 정합성과 권한 있는 다운로드를 확인한다.
- 사용 관측 자료는 제품 개선에 쓰고 개인 성과 점수로 사용하지 않는다.

## 기술·운영 제약

- React·TypeScript, Node.js·NestJS·TypeScript(Express), PostgreSQL·Prisma를 사용한다.
- 개발은 PostgreSQL만 Docker로, 웹·API는 로컬에서 실행한다.
- 초기 운영은 GCP 서울 리전의 단일 VM과 Docker Compose를 사용한다.
- DB와 첨부 원본은 영구 디스크에 보관하고, 정합성 있는 백업 세트를 하루 1회
  Cloud Storage에 저장하여 7일 보관한다. 백업 성공과 복구 성공은 별도로 검증한다.
- 개발·검증·운영 데이터를 분리한다. 비밀값을 Git에 저장하지 않으며 첨부는 권한 확인 후 제공한다.
- 패키지 버전은 구현 전에 호환성을 확인하고 고정한다. 상세 미결정 사항은 기술 설계에서 추적한다.
- 무료 크레딧의 자격·잔액·만료와 이후 비용은 배포 전에 확인한다. 상시 무료 운영을 전제하지 않는다.

## 개발 절차와 품질 기준

1. 기존 제품 명세·기술 설계·결정 기록을 읽고 기능 명세를 작성한다.
2. 구현 계획에서 이 헌법의 각 원칙을 점검한다. 해당 없음은 이유를 남기고 충돌은 구현 전에 해결한다.
3. 수용 조건별 구현·검증 작업을 분해하고, 명세 변경이 생기면 계획과 작업 목록을 함께 갱신한다.
4. `develop` 기반 `feature/<기능명>`에서 구현한다. Spec Kit의 기본 브랜치 명칭보다 이 규칙을 우선한다.
5. 기능 검증과 리뷰 후 `develop`에 병합하고 통합 테스트를 거쳐 최종적으로 `main`에 병합한다.
   기본 브랜치는 `main`이며 직접 push하거나 기능 브랜치에서 바로 병합하지 않는다.
6. 사용자 승인 없는 병합·강제 push를 수행하지 않는다. 문서 작성은 배포나 외부 전송 승인이 아니다.

모든 작업은 현재 저장소 루트를 기준으로 수행한다. 문서 원본과 기능 산출물은 저장소 안에서 관리한다.
임시 메모는 Git에서 제외한 `work/`, 안내 산출물은 `outputs/`에 둔다.
Spec Kit 기능 산출물의 경로는 활성 템플릿·스크립트와 일치시켜 하나만 사용하며 문서를 이중 관리하지 않는다.
기존 사용자 변경과 로컬 전용 변경은 보존하고, 커밋 시 작업 범위를 명시적으로 선택한다.

## Governance

- 이 헌법은 프로젝트의 공통 개발 원칙이다. 제품 명세는 동작, 기술 설계는 기술 선택,
  `AGENTS.md`는 에이전트 실행 지침을 담당한다. 충돌을 발견하면 임의 해석으로 구현하지 않고
  사용자와 해당 결정을 확인한 뒤 관련 문서를 정합하게 수정한다.
- 개정 시 이유, 변경 원칙, 영향을 받는 명세·계획·기존 기능, 필요한 전환 절차를 기록하고
  프로젝트 소유자의 승인을 받아 채택한다. 기존 합의나 권한 정책을 묵시적으로 바꾸지 않는다.
- 버전은 SemVer를 따른다. 원칙 삭제·호환되지 않는 재정의는 MAJOR,
  원칙 추가·실질적 지침 확장은 MINOR, 의미를 바꾸지 않는 표현 수정은 PATCH로 올린다.
- 모든 기능 계획과 병합 전 리뷰는 헌법 준수 여부를 확인한다.
  예외가 필요하면 이유·범위·기간·보완책을 기록하고 소유자 승인 후 적용한다.
- 대화의 명시적 변경 요청은 개정의 입력이다. 영구 원칙 변경은 헌법과 관련 문서에 기록하여 추적한다.
