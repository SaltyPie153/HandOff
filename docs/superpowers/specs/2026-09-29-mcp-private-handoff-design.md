# MCP 요청과 근거 기반 회신 설계

작성일: 2026-09-29
상태: 사용자 설계 검토용. 구현·연동 검증 전.

후속 구현: 서버 자동 확인기의 모델 호출은 Upstage `solar-pro4`로 확정·검증했다. 아래 Codex Agents API 설명은 초기 실행기 후보 이력이다. 최신 공급자와 확인 결과는 [기술 설계](../../product/technical-design.md)를 따른다.

## 목적과 합의한 범위

4~5명 프로젝트 팀에서 요청은 주 송신자 A와 주 수신자 B가 주고받되, 팀은 요청 제목과 게시된 회신을 함께 본다. A의 Codex는 작업 중 필요를 판단하면 MCP를 통해 요청을 자동 전송한다. B의 PC와 데스크톱 Codex가 꺼져 있어도 서버의 Codex 작업이 자료를 확인하고, 명시된 최신 근거만으로 답할 수 있을 때 사실 확인 회신을 자동 게시한다. 근거가 부족한 판단·추천은 자동 게시하지 않고 B가 웹에서 검토한다.

이 설계는 [제품 원본 명세](../../product/spec.md)의 기존 '사람이 최종 전송' 및 '전송된 본문을 팀 전체 열람' 규칙을 변경한다. 프로젝트 멤버십과 서비스 가입 승인, 사람의 인수인계 확인 완료·계약 동의 구분은 유지한다.

## 읽기·쓰기 경계

| 자료 또는 행위 | 접근 주체 |
|---|---|
| 전송 전 초안 | 작성 주체 A만. Codex 작업은 A에게 위임된 범위에서만 접근 |
| 전송된 요청 제목과 공개 회신 | 현재 프로젝트 멤버 전원 |
| 일반 인수인계 요청 본문·첨부·비공개 버전·상세 이력 | A와 B. 계약의 명시적 필수/참조 참여자는 해당 버전의 추가 당사자로 취급 |
| B의 자동 회신 후보·근거 검토 메모 | B만. 게시 전에는 팀 피드에 노출하지 않음 |
| 사람의 확인 완료·계약 동의 | 해당 버전의 권한 있는 사람만. MCP와 배경 Codex에는 해당 상태 변경 권한 없음 |
| 이미 확정된 계약의 현재 유효본 | 기존 제품 명세의 프로젝트 공개 정책을 유지. 검토 중인 제안은 위의 비공개 요청 경계를 따름 |

요청 제목은 전송 시부터 공개 정보다. 팀 피드에서 비당사자는 제목·공개 회신·회신 작성 주체와 시각만 볼 수 있다. 요청 상세 주소나 공개 회신 ID를 알아도 본문·첨부·비공개 버전이나 B의 초안을 얻지 못한다. 서비스 관리자도 프로젝트 배정만으로 모든 요청의 비공개 본문을 얻지 못한다. 멤버십 또는 당사자 자격이 사라지면 서버가 다음 조회와 자동 작업에서 현재 권한을 다시 검사한다. 과거 감사 이력은 보존한다.

사람 B가 공개 회신을 게시할 때는 비공개 요청의 내용을 어디까지 공개할지 직접 판단한다. 웹은 공개 대상과 내용을 게시 전에 보여준다. 자동 게시 회신은 별도의 엄격한 근거 검사와 최소한의 사실 문장으로 제한한다. 요청 제목·본문·첨부를 회신에 자동으로 복사하지 않는다.

## 요청 전송과 배경 실행

1. A가 프로젝트별 자동 전송 권한을 연결·해제할 수 있다. A의 Codex는 범위가 제한된 MCP 도구로 수신자 B, `publicTitle`, `privateBody`, 비공개 첨부 참조, 전송 키를 구분해 제출한다. 서비스는 A와 B의 현재 가입 승인·프로젝트 멤버십과 도구 권한을 검사한다. 웹에 별도의 사람 최종 전송 버튼을 요구하지 않는다.
2. DB가 요청·불변 첫 버전·감사 이력·배경 작업 이벤트를 함께 저장한다. 같은 전송 키와 같은 입력의 재시도는 기존 결과를 돌려주고, 같은 키의 다른 입력은 거부한다. Codex가 전송했음을 사람의 직접 전송과 구분해 기록한다. 자동 전송은 송신자의 계약 동의로 계산하지 않는다.
3. 저장된 이벤트가 B를 위한 서버 작업을 시작한다. 데스크톱 Codex나 B의 PC가 꺼져 있어도 실행 가능해야 한다. [관리형 Codex Agents API](https://developers.openai.com/api/docs/guides/agents-api/overview)는 우선 검증할 실행기 후보이며, 실제 연결·비용·보안·GitHub 접근은 구현 전 작은 기술 검증으로 확인한다. 실행기 선택과 무관하게 HandOff DB가 요청·회신의 원본이다.
4. 서버 작업은 B의 현재 권한으로 요청과 필요한 근거를 읽고, GitHub는 승인된 저장소·참조를 읽기 전용으로 사용한다. 코드 수정, PR 작성, 계약 동의, 인수인계 확인 완료는 할 수 없다. 결과를 게시하기 직전에 B의 가입·프로젝트 자격, 요청 최신 버전과 상태를 다시 확인한다.

## 근거 등록과 자동 회신 판정

근거는 (1) HandOff의 현재 확정 계약 버전, (2) 프로젝트에 연결한 GitHub 저장소의 B가 신뢰 근거로 지정한 파일과 조회 시 커밋 SHA, (3) B가 지정해 동기화를 허용한 로컬 계약 파일의 스냅샷이다. 로컬 커넥터는 지정 경로만 읽고 해시·버전·동기화 시각과 내용을 서버에 전송한다. 지정 취소 시 이후 자동 작업에서 제외한다. PC가 꺼졌을 때 서버는 PC 파일의 현재 상태를 직접 증명할 수 없으므로, 마지막 스냅샷을 무조건 '최신'으로 취급하지 않는다. 설계 기본값으로 마지막 성공 동기화 후 24시간 이내이고 미동기화 변경이 보고되지 않은 스냅샷만 자동 근거로 인정한다. 그 밖에는 B의 검토로 넘긴다.

파일 경로 허용은 B와 프로젝트에 묶고, 전체 PC나 저장소를 기본 동기화하지 않는다. 동기화된 내용과 GitHub 연결 자격은 비공개 저장·접근 제어의 대상이다. B가 경로 지정을 취소하면 활성 근거의 본문을 제거하고, 해시·시각 등 최소 감사 정보만 남긴다. 이미 게시된 회신은 과거 이력으로 유지한다. 백업에 남는 사본의 만료는 제품의 보관 정책을 따른다.

자동 게시의 필요 조건은 요청의 확인 대상이 특정되고, 신뢰 대상으로 등록한 자료의 명시적 문구가 그 대상을 직접 뒷받침하며, 근거의 버전이 요청 버전과 맞고, 사용 가능한 근거끼리 충돌하지 않는 것이다. HandOff는 현재 확정 계약 ID와 버전, GitHub는 커밋 SHA, 로컬 파일은 해시와 동기화 시각을 실행에 고정한다. 자료에 없다는 사실만으로 부정 답변을 만들거나, 추론·추천·예상 일정을 사실로 게시하지 않는다. HandOff 확정 계약과 파일 내용이 충돌하면 자동 답변을 중단한다.

조건을 만족하면 짧은 사실 확인 회신을 팀에 자동 게시하고 `Codex 자동 회신`, 근거 종류·버전, 요청 버전, 실행 ID를 감사 기록에 남긴다. 비당사자에게는 비공개 파일 경로·원문·첨부 또는 비공개 근거 링크를 노출하지 않는다. 자동 회신은 의견/사실 확인 기록이며 인수인계 확인 완료나 계약 동의 기록이 아니다. 동일 요청 버전의 동일 실행 결과를 재시도해도 공개 회신은 하나만 생긴다.

조건을 만족하지 못하면 공개 회신을 만들지 않는다. 이유와 참조 가능한 근거를 B만 볼 수 있는 검토 화면에 남긴다. B는 웹에서 회신을 작성·수정하고 공개 범위를 미리 확인한 뒤 팀에 게시한다. 근거가 부족한 상태에서 배경 작업이 반복해 임의 답변을 게시하지 않는다.

## 화면과 단계

- 공통 공간: 팀 공개 제목과 게시된 회신 피드. 비당사자가 제목을 선택해도 비공개 요청 상세는 열리지 않는다.
- 내 받은함·보낸함: 자신이 당사자인 요청의 본문·첨부·버전과 상태. B의 근거 부족/충돌 검토 항목도 받은함에 보인다.
- 요청 상세: 당사자에게 공개 회신과 비공개 요청을 연결해 보여준다. 사람의 확인·동의 상태와 Codex의 조회·자동 답변 이력을 분리한다.
- 첫 구현 단위: MCP 사용자 연결·권한과 비공개 요청 저장. 다음 단위: 근거 등록·로컬 동기화·배경 판정. 다음 단위: 팀 공개 피드와 B의 웹 검토·게시. 개발 계약의 버전 합의와 Discord 알림은 각각 별도 구현 단위다.

## 검증 기준

1. A의 Codex가 전송한 요청의 제목은 현재 팀원에게 보이고, 본문·첨부·버전은 A·B(및 명시적 계약 참여자) 외에는 API와 화면에서 차단된다.
2. 승인 전 회원, 미배정 회원, 해제된 MCP 연결, 잘못된 프로젝트·수신자, 제외된 회원은 전송·조회·배경 회신이 거부된다.
3. B의 PC가 꺼진 상태에서도 서버 실행기는 등록된 HandOff·GitHub·로컬 스냅샷 근거를 검사한다. 최신 명시 근거가 있을 때만 자동 공개 회신이 하나 게시된다.
4. 근거 부재, 충돌, 오래된 동기화본, 모호한 추론·추천에서는 자동 공개 회신이 없고 B에게 비공개 검토 항목이 생긴다.
5. B가 웹에서 게시한 회신은 팀원 모두가 볼 수 있으며, 미게시 초안은 B만 볼 수 있다. 사람이 확인·동의를 누르기 전에는 그 상태가 바뀌지 않는다.
6. 요청 저장 직후·배경 실행 직후 응답 유실을 재현해도 요청 버전, 실행 결과, 공개 회신이 중복되지 않는다. 근거·토큰·비공개 요청 본문은 로그와 팀 공개 피드에 유출되지 않는다.

## 검증 전제와 한계

현재 저장소에는 이 MCP·배경 실행·로컬 동기화 기능이 없다. 관리형 Agents API의 실제 인증 방식, 계정별 비용과 사용 한도, GitHub 및 로컬 스냅샷의 연결 방법은 기술 검증 후 실행 계획에 고정한다. 자동 판정은 자유로운 문장 이해만으로 기밀 비노출을 보증할 수 없다. 따라서 근거 직접 일치·최소 공개 출력·서버 측 권한과 중복 검사로 자동 게시 범위를 제한하고, 애매한 경우 B의 검토로 넘긴다.
