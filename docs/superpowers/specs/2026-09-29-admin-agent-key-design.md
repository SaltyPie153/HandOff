# 서버 Codex API 키 웹 설정 설계

작성일: 2026-09-29
상태: 사용자 문서 검토 승인

## 목적과 범위

서비스 관리자가 HandOff 웹의 `/settings`에서 서버 자동 회신용 OpenAI API 키를 등록·교체·삭제한다. 키는 API 재시작 뒤에도 유지한다. 이번 범위는 `OPENAI_API_KEY` 한 종류이며, 프로젝트별 MCP 토큰, 로컬 근거 암호화 키, GitHub 읽기 토큰의 설정 UI는 포함하지 않는다. 자동 회신의 근거·권한·공개 범위 판정 규칙은 기존 [MCP 요청 설계](2026-09-29-mcp-private-handoff-design.md)를 유지한다.

키는 서버 전체의 관리형 Agents API 호출에만 쓴다. 입력한 관리자의 개인 Codex 자격이나 계약 동의 권한으로 해석하지 않는다. 키 등록만으로 자동 회신이 허용되지 않는다. 요청에 명시적인 `KEY: value` 확인 주장과 최신 허용 근거가 모두 있어야 한다.

## 선택한 저장 방식

- 서버가 관리하는 전용 파일을 웹 배포 경로와 Git 추적 경로 밖에 보관한다. 개발 기본 경로는 저장소의 Git 제외 `work/server-secrets/`이며, 운영은 `HANDOFF_SECRET_DIR`로 VM 영구 디스크의 별도 경로를 지정한다. 운영에서 경로가 없으면 설정 저장을 거부한다.
- 파일 내용은 API 키 또는 명시적인 비활성 상태와 변경 세대 ID를 담는다. 서버는 같은 디렉터리의 임시 파일에 쓴 뒤 원자적으로 교체한다. Linux에서는 디렉터리 `0700`, 파일 `0600` 권한을 강제한다. Windows에서는 현재 사용자만 읽을 수 있는 ACL을 확인·적용하고 실패하면 저장을 거부한다. 웹 정적 파일과 API 응답은 이 경로를 제공하지 않는다.
- 파일 자체를 별도 암호화하지 않는다. 서버 사용자·관리자의 OS 파일 접근 권한과 VM 디스크 보안이 보호 경계다. DB·Git·일반 로그에는 키를 쓰지 않는다. DB 백업과 별도로 취급하며 VM 재해 복구 시 관리자가 재입력할 수 있다.
- 기존 서버 환경 변수 `OPENAI_API_KEY`는 호환성을 위해 파일이 없을 때만 읽는다. 웹에서 저장한 키가 우선한다. 웹에서 삭제하면 비활성 상태 파일을 남겨 환경 변수로 되돌아가지 않게 한다. 다시 등록하면 비활성 상태를 새 키로 교체한다.
- 파일이 손상되거나 권한 검사가 실패하면 자동 회신을 중단하고 수신자 검토로 보낸다. 키 값, 파일 경로, 상세 실패 원인은 브라우저와 일반 로그에 반환하지 않는다.

## 웹과 API

- 승인된 서비스 관리자에게만 `/settings`의 ‘서버 Codex API 키’ 구역을 보인다. `type=password`, 자동 완성 억제 입력과 ‘저장·교체’, ‘사용 중지’ 버튼을 둔다. 일반 회원과 프로젝트 관리 담당자에게는 이 구역을 보이지 않는다.
- `GET /api/admin/agent-key`는 `configured`와 상태 종류만 반환하며 키 값, 일부 문자, 파일 경로, 해시를 반환하지 않는다. `PUT /api/admin/agent-key`는 키 문자열을 받아 저장하고 값 없는 성공 상태만 반환한다. `DELETE /api/admin/agent-key`는 비활성 상태를 기록한다.
- 모든 경로는 현재 DB의 승인된 서비스 관리자 자격을 검사한다. 변경 경로에는 기존 세션 CSRF 검사를 적용한다. 모든 응답은 `Cache-Control: no-store`다. 요청 본문이나 오류에 키를 기록하지 않는다. 형식과 길이를 제한하고 잘못된 입력은 고정된 오류로 거부한다. 운영 웹에서는 HTTPS가 전제다.
- 저장 또는 오류 뒤 웹 입력 상태를 지우며, 페이지를 다시 열어도 키를 되돌려 표시하지 않는다. 사용자에게는 설정 여부와 재시작 후 유지 여부만 알린다.

## 워커와 수명 주기

- 서버 키 저장소를 관리형 Agents 어댑터와 배경 워커의 단일 키 출처로 사용한다. 각 작업에서 현재 키 상태와 세대 ID를 읽는다. 저장 시 ‘서버 Codex 확인 불가’로 멈춘 수신자 검토 작업을 다시 큐에 올린다.
- 키가 없거나 비활성 상태이면 외부 Agents API를 호출하지 않는다. 처리 중 키가 교체·삭제되면 게시 직전에 세대 ID를 재검사하고 자동 게시를 중단해 B의 검토로 넘긴다.
- 사람의 웹 회신과 `CODEX_AUTO` 회신은 기존과 같이 구분한다. 키 설정·변경은 계약 동의나 인수인계 확인 완료를 만들지 않는다.

## 검증 기준

1. 서비스 관리자만 상태 조회·등록·교체·사용 중지를 할 수 있다. 일반 회원, 미승인 회원, 프로젝트 관리 담당자, CSRF 없는 변경 요청은 거부된다.
2. API 응답·웹 화면·일반 로그·Git 상태·DB에서 키 문자열이 나타나지 않는다. 브라우저는 저장 뒤 입력값을 지운다.
3. 저장 후 API 프로세스를 재시작해도 키가 사용 가능하다. 사용 중지 후에는 환경 변수 키가 남아 있어도 새 자동 회신이 없다.
4. 키 입력만으로는 자동 게시가 생기지 않는다. 명시 근거가 있는 요청만 기존 판정을 통과하며 근거 부족·충돌·오래된 로컬 스냅샷은 B 검토로 간다.
5. 키 교체·삭제가 Agents 호출 도중 발생하면 그 호출 결과를 자동 게시하지 않는다. 중복 실행에도 공개 회신은 하나만 남는다.
6. 파일 권한 또는 내용이 잘못되면 키를 반환하거나 사용하지 않고 안전하게 실패한다.

## 대안과 결정 이유

암호화된 DB 저장은 별도의 영구 마스터 키와 복구 절차를 추가로 요구한다. GCP Secret Manager는 운영 배포 뒤 적합하지만 현재 로컬 시험에 GCP 연동을 요구한다. 서버 전용 보호 파일은 사용자가 선택한 재시작 후 보존과 현재 단일 VM 설계에 맞는다. 운영 배포 전에는 영구 디스크 마운트·OS 권한·재해 복구 시 재입력 절차를 별도 검증한다.
