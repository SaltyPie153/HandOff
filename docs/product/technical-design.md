# HandOff 기술 설계 및 운영 결정

상태: 기술·운영 결정 반영 · 로컬 앱 기본 골격 구현 중 · 업무 기능 및 운영 배포 전

제품 동작의 원본은 [제품 명세](spec.md)이며, 이 문서는 선택한 기술과 운영 조건을 정리한다. 구현되지 않은 설정이나 연동을 동작한다고 간주하지 않는다.

## 1. 확정 기술

| 영역 | 결정 |
|---|---|
| 프론트엔드 | React + TypeScript |
| 백엔드 | Node.js + NestJS + TypeScript, 기본 Express 어댑터 |
| 데이터베이스 | PostgreSQL, 직접 운영 |
| ORM | Prisma |
| 로그인 | Google 및 Discord 소셜 로그인 |
| 회원 접근 | 로그인·가입 후 서비스 관리자 승인 |
| 배포 | GCP Compute Engine VM 한 대, 서울 asia-northeast3 |
| 컨테이너 운영 | Docker + Docker Compose |
| 첨부 원본 | VM 영구 디스크 |
| 백업 | DB와 첨부를 하루 1회 Cloud Storage에 백업, 7일 보관 |
| 비용 방향 | 비용 최소화, 자격·만료일을 확인한 신규 무료 크레딧 활용 |
| Codex | 연결 방식과 권한 검증 후 연동. 방식 자체는 아직 미확정 |
| Discord 알림 | 프로젝트별 요청·회신 알림. 소셜 로그인과 별개로 설정 |

앱 기본 골격의 근거는 [구현 계획](../../specs/001-app-bootstrap/plan.md)과 [조사 기록](../../specs/001-app-bootstrap/research.md)이다. npm workspaces, Vite, MUI Material/Emotion을 사용한다. 현재 저장소의 `.node-version`은 Node.js 24.21.0, `package.json`의 엔진 범위는 `>=24.15 <25`, 패키지 관리자는 npm 10.9.2다. 로컬 검증 기록의 번들 Node.js 24.19.0도 이 범위 안이다. 루트·각 workspace의 `package.json`과 `package-lock.json`은 React 19.3.0, Vite 8.3.0, NestJS 12.0.3, Prisma CLI/client/adapter 7.10.0, TypeScript 5.9.3, MUI Material 9.4.0, Vitest 5.0.1, Playwright 1.63.0을 고정한다. `compose.dev.yml`과 `compose.test.yml`의 DB는 `postgres:17.11-bookworm` 및 digest `sha256:639ab7ceb90e13123085b741fb31ef493fba25463002f6da665352e7b534b652`로 고정했다. 이는 개발·시험 구성이다. Prisma 선택만으로 계약 동시 처리·중복 방지가 보장되지는 않으며 제품 명세의 상태 검증과 DB 제약·트랜잭션으로 구현한다.

## 2. 개발 및 운영 환경

### 개발

- React·NestJS는 개발자 PC에서 실행한다. 현재 루트 `npm run dev:web`과 `npm run dev:api`가 각각 loopback 웹·API를 시작한다.
- PostgreSQL은 Docker 컨테이너로 실행한다. 개발 DB는 `npm run db:up`/`npm run db:down`으로 관리하며 named volume을 유지한다.
- 개발용 DB·첨부·계정 설정은 운영 환경과 분리한다.
- `npm run test:integration`은 `handoff-foundation-*` 전용 Compose 프로젝트·volume에서 빈 시험 DB migration을 먼저 확인하고, `handoff-test-*` 전용 fixture에서 통합 검사를 수행한다. `npm run test:e2e`는 `handoff-test-*` fixture를 사용한다. 두 프로젝트는 각자 만든 시험 자원의 정리를 시도하며 실패를 보고한다. 시험 포트는 loopback 5433/3001/5174이고 기존 `handoff-dev` DB를 내리지 않는다. CI 자체는 아직 구성되지 않았다.
- 웹 상태 화면과 `GET /api/health/ready`는 개발 DB 연결·BootstrapProbe 스키마 상태를 확인한다. `npm run probe -- create --id <UUID> --value <TEXT>`, `npm run probe -- verify --id <UUID> --value <TEXT>`, `npm run probe -- cleanup --id <UUID>`, `npm run verify:bootstrap -- --id <UUID> --value <TEXT>`는 개발·시험 전용 도구다. 수동으로 호출하면 현재 개발 DB의 자료를 다루므로 DB 소유권을 먼저 확인한다. 자동 보존·장애 검증은 [Quickstart](../../specs/001-app-bootstrap/quickstart.md)의 격리 시험 명령을 사용한다.
- `pwsh -NoProfile -File scripts/check-harness.ps1` 기본 실행은 문서 검사만 하며 `PRODUCT: NOT_RUN`을 출력한다. `-RequireProduct` 또는 `scripts/check-product.ps1` 직접 실행은 build, typecheck, test, test:integration, test:e2e를 순서대로 실행하고 실패 코드를 전달한다. 이 제품 검사는 앱 기본 골격 범위이며 [R01~R25](../harness/checks.md)의 업무 기능 완료가 아니다.

### 운영

초기 팀원 4~5명은 모두 한국에서 접속한다. 이 사용 위치를 기준으로 서울 리전을 선택했다.

```text
브라우저
   ↓ HTTPS
GCP 서울 VM · Docker Compose
├─ 웹 서버: React 빌드 파일 제공, API 연결
├─ API: NestJS + Prisma
└─ PostgreSQL: 직접 운영
       ↓
VM 영구 디스크: DB 데이터 / 첨부 파일
       ↓ 하루 1회, 백업 묶음의 시점 정합성 확인
Cloud Storage: DB·첨부 백업, 7일 보관
```

- 운영 데이터는 컨테이너의 쓰기 레이어나 임시 폴더에만 저장하지 않는다. VM 영구 디스크에 연결된 볼륨 또는 마운트를 사용한다.
- 첨부는 공개 정적 폴더로 노출하지 않고 서버에서 회원 승인·프로젝트 권한·초안 소유권을 검사한 뒤 내려준다.
- DB는 애플리케이션용 내부 연결을 사용하고 인터넷에 무제한 공개하지 않는다.
- Docker 도입은 DB 업데이트·백업·복구 책임을 대체하지 않는다. 운영 볼륨을 지우는 초기화 명령을 일반 배포 절차에 넣지 않는다.
- 웹 서버 종류, 이미지 레지스트리, 자동 배포 방법, VM 크기·디스크 용량은 아직 확정하지 않았다.
- 서울 VM은 상시 무료 사용을 전제하지 않는다. 무료 크레딧 잔액·만료 후 운영 비용을 배포 전에 확인한다. 유료 전환이나 GCP 리소스 생성은 아직 수행하지 않았다.

## 3. 회원과 계정 연결

1. Google 또는 Discord로 처음 로그인하면 가입 승인 대기 상태다.
2. 승인 전에는 대기 화면만 제공하고 프로젝트 목록·본문·첨부·생성 API 접근을 차단한다.
3. 서비스 관리자가 승인하면 프로젝트 생성이 가능하다. 기존 프로젝트는 별도 배정이 필요하다.
4. 로그인한 사용자가 다른 제공자의 인증을 완료해 로그인 수단을 연결한다. 이메일이 같다는 이유로 자동 병합하지 않는다.
5. 두 로그인 수단은 하나의 내부 회원 ID와 승인 상태·멤버십·받은함을 공유한다.
6. 이미 다른 회원에게 연결된 제공자 계정을 덮어쓰거나 두 회원의 데이터를 자동 병합하지 않는다. 별도 처리 정책이 정해질 때까지 연결 충돌로 안내한다.

실제 최초 관리자는 사용자 본인의 계정으로 배포 시 명시적으로 지정한다. 첫 방문자를 자동 관리자로 승격하지 않는다. 이후 서비스 관리자가 다른 승인 회원에게 서비스 관리자 권한을 부여할 수 있다. 계정 식별값·초기 등록 절차는 배포 전에 확인한다.

로그인 계정 연결과 Discord 알림 채널 연동은 다른 기능이다. Google 로그인 사용자에게 Discord 계정 연결이 필수인지, 미연결 사용자에게 알림 멘션을 어떻게 처리할지는 아직 미확정이다.

## 4. 서비스 권한과 프로젝트 권한

| 주체 | 확정 권한 |
|---|---|
| 승인 대기 회원 | 승인 대기 화면 확인. 프로젝트 접근·생성 불가 |
| 서비스 관리자 | 가입 승인, 서비스 관리자 권한 부여, 승인 회원의 프로젝트 배정 |
| 승인 회원 | 프로젝트 생성. 기존 프로젝트는 배정된 경우에만 접근 |
| 프로젝트 생성자 | 생성 시 해당 프로젝트 멤버 및 관리 담당자로 등록 |
| 프로젝트 관리 담당자 | 자기 프로젝트에 가입 승인된 회원 추가·제외 |
| 프로젝트 멤버 | 해당 프로젝트의 전송된 인수인계 본문·첨부·이력 열람, 자신의 요청 처리 |

서비스 관리자 역할만으로 모든 프로젝트 본문을 열람하거나 다른 사람의 초안을 조회할 수 있다는 예외는 두지 않는다. 콘텐츠 접근에는 프로젝트 배정을 요구한다. 프로젝트 관리 담당자는 다른 프로젝트의 멤버·가입 승인·서비스 관리자 권한을 바꿀 수 없다.

프로젝트 멤버 관리 권한과 계약 동의 권한은 별개다. 관리자가 다른 담당자의 확인을 대신할 수 없다. 멤버 제외로 미완료 요청 담당자가 접근 권한을 잃으면 제품 명세의 담당자 변경 필요·관리 종료 절차를 따른다.

프로젝트 관리 담당자의 추가 지정·양도, 마지막 관리자 제거 방지, 가입 거절·계정 비활성화 및 재가입 처리는 추가 결정 대상이다. 승인되지 않은 자동 승격이나 임의 계정 복구를 구현하지 않는다.

## 5. 백업 정책과 복구 검증

- PostgreSQL 데이터와 첨부 파일을 하루 한 번 VM 외부 Cloud Storage로 백업한다.
- 보관 기간은 7일이다. 파일 원본 저장 위치는 계속 VM이다.
- 같은 백업 세트의 DB 참조와 첨부가 일치하도록 일관된 시점을 확보한다. DB 파일 디렉터리를 실행 중 그대로 복사하는 방식만으로 유효한 백업이라고 간주하지 않는다.
- 백업 세트에는 생성 시각과 성공 여부를 기록하고, 실패를 성공으로 표시하지 않는다.
- 운영 전 별도 복구 환경에서 DB를 복원하고 첨부 참조·다운로드를 확인한다. 업로드 성공만으로 복구 검증을 대체하지 않는다.
- 구체적인 백업 시각, 보관 만료 처리, 실패 알림, 정합성 확보 방법, 복구 목표 시간은 구현 전에 정한다. 백업이 실패하면 마지막 유효 백업 이후 손실 범위가 하루를 넘을 수 있다.

## 6. 기능 구현 순서 제안

아래는 의존성을 설명하는 순서다. 1단계의 로컬 골격과 검사 명령은 마련됐지만 팀원 재현 및 최종 검증이 남아 있다. 2~7단계는 후속 범위다.

1. 버전·패키지 관리·폴더 구조 확정, 로컬 PostgreSQL Compose와 제품 검증 진입점 구성.
2. 회원·제공자 계정·가입 승인·최초 관리자, API 인증 기반 구현.
3. 프로젝트 생성·관리 담당자·멤버 배정과 권한 테스트 구현.
4. 초안·본문·첨부·받은함·보낸함 구현.
5. 버전별 확인·동의·수정 요청·폐기·동시성·중복 방지 구현.
6. Discord 알림과 재시도, Codex 연결 가능성 검증 및 검증된 연동 구현.
7. 운영 Compose·백업·복구·OAuth 운영 설정, develop 통합 테스트 후 main 최종 반영과 배포.

각 기능은 `develop` 기반 `feature/<기능명>`에서 작업하고 `develop` 통합 테스트를 거쳐 `main`에 최종 병합한다. 현재 `feature/app-bootstrap`에는 로컬 웹·API·DB 골격과 검증 도구가 구현돼 있다. 이 브랜치는 아직 `develop`에 병합되지 않았고 운영 배포도 하지 않았다.

## 7. 남은 확인 사항

| 시점 | 질문 또는 기술 검증 대상 |
|---|---|
| 앱 기본 골격 완료 전 | 패치와 lockfile 고정 완료. 새 사본에서 팀원 최초 실행·ready 확인, 최종 수용 검증 대기. 라우팅은 화면 확장 시 선정 |
| 인증 구현 전 | 웹 세션 방식과 수명, 계정 연결 충돌·해제, 가입 거절·관리자 양도 정책 |
| 첨부 구현 전 | 허용 형식·최대 용량, 보존·삭제 정책 |
| 외부 연동 전 | Codex 인증·접속 방식, Discord 봇/웹훅과 채널 권한, 미연결 회원 알림 |
| 배포 전 | 도메인, GCP 프로젝트·무료 크레딧 실제 상태, VM 사양, 최초 관리자 식별값, OAuth 앱 설정 |
| 운영 시작 전 | 백업 시각·실패 알림·복구 절차, develop 테스트 환경과 CI/CD 도구·자동화 범위 |

이 항목들은 사용자에게 확인하거나 검증해야 할 미결정 사항이다. 기존에 선택한 React·NestJS·Prisma 등을 다시 미정으로 돌리지 않는다.
