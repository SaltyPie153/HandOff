# 제품 검증 기준

[제품 명세](../product/spec.md)의 14장 기준. 모든 제품 기준은 현재 미구현/미검증이다. Harness 테스트와 혼동하지 않는다. 기술·운영 정책은 [기술 설계](../product/technical-design.md)를 따른다.

| ID | 기준 | 상태 |
|---|---|---|
| R01 | 승인된 사용자가 로그인 후 배정된 프로젝트를 선택하면 해당 공통 공간이 먼저 열린다. 미승인 사용자는 대기 화면만 본다. | 미구현/미검증 |
| R02 | 공통 공간에서 다른 팀원 간 전송된 요청의 본문과 첨부를 열람할 수 있다. | 미구현/미검증 |
| R03 | 같은 프로젝트 팀원이어도 남의 초안이나 남의 응답 버튼에는 접근할 수 없다. | 미구현/미검증 |
| R04 | 수신자가 확인하면 송신자 보낸함 상태가 갱신되고 회신 알림이 생성된다. | 미구현/미검증 |
| R05 | 수정 요청 의견이 원래 송신자에게 전달되고 재전송은 같은 요청의 새 버전이 된다. | 미구현/미검증 |
| R06 | 새 버전은 이전 확인을 승계하지 않고 재검토 대상으로 표시된다. | 미구현/미검증 |
| R07 | 개발 계약에서 필수 PM의 동의는 확정 조건이며 참조 PM의 열람은 조건이 아니다. | 미구현/미검증 |
| R08 | 새 변경안 검토·수정·철회가 기존 확정본을 바꾸지 않는다. | 미구현/미검증 |
| R09 | 오래된 화면에서 체크하거나 중복 클릭해도 잘못된 확정·중복 회신이 생기지 않는다. | 미구현/미검증 |
| R10 | 디스코드 장애 중에도 웹에서 요청을 생성하고 처리할 수 있다. | 미구현/미검증 |
| R11 | 다른 팀·프로젝트의 API와 첨부 접근을 차단한다. | 미구현/미검증 |
| R12 | Codex 조회는 사람의 승인으로 처리되지 않고, 연동 자격으로 승인 API를 호출할 수 없다. | 미구현/미검증 |
| R13 | 철회와 마지막 동의를 동시에 시도하면 하나만 성공한다. 철회된 버전은 확정되지 않고, 확정된 버전은 철회되지 않는다. | 미구현/미검증 |
| R14 | 수정 요청·확정·철회·관리 종료된 버전에는 새로운 응답을 저장하지 않는다. 동일 응답 재시도는 기존 결과만 반환하며 동의에서 수정 요청으로 바꾸는 호출은 거부한다. | 미구현/미검증 |
| R15 | 송신자·수신자·필수 PM이 접근 권한을 잃으면 미완료 요청은 담당자 변경 필요가 된다. 관리 종료와 연결 요청 생성 후에도 이전 확인을 승계하지 않고 기존 확정 계약을 유지한다. 참조자 이탈은 검토를 막지 않는다. | 미구현/미검증 |
| R16 | 폐기 검토 중에는 기존 계약이 유효하며, 폐기 확정 후 웹·Codex의 유효 계약 목록에서는 제외된다. 직접 조회에서는 폐기 상태와 과거 기록을 구분해 보여준다. | 미구현/미검증 |
| R17 | 서버 저장 직후 응답 유실을 재현하고 동일 전송을 재시도하면 요청·버전·알림 이벤트 수가 늘지 않는다. 다른 탭의 동일 초안 리비전 전송도 중복 발행되지 않는다. | 미구현/미검증 |
| R18 | 수신자 동의 후 필수 PM만 대기하면 수신자의 확인 필요 건수는 0이고 전체 상태는 PM 확인 대기이다. 새 버전 전송 후에는 수신자의 재검토 필요 건수가 다시 증가한다. | 미구현/미검증 |
| R19 | 같은 계약의 경쟁 변경안과 오래된 기준 확정본으로 합의를 시도하면 차단된다. 관리 종료 후 새 담당자의 연결 요청도 같은 계약 ID와 유효성 규칙을 유지한다. | 미구현/미검증 |
| R20 | Google·Discord 신규 가입자는 승인 전 프로젝트 조회·생성·첨부 다운로드 API를 사용할 수 없다. 서비스 관리자 승인 후에도 배정되지 않은 프로젝트에는 접근하지 못한다. | 미구현/미검증 |
| R21 | 승인 회원이 프로젝트를 생성하면 해당 프로젝트의 멤버·관리 담당자가 된다. 다른 프로젝트의 권한은 얻지 않는다. | 미구현/미검증 |
| R22 | 프로젝트 관리 담당자는 승인 회원만 자기 프로젝트에 추가·제외할 수 있다. 다른 프로젝트 멤버 변경·가입 승인·서비스 관리자 권한 부여 시도는 차단된다. | 미구현/미검증 |
| R23 | 명시적으로 지정된 최초 관리자만 초기 관리자 권한을 받고, 서비스 관리자만 다른 승인 회원에게 그 권한을 부여한다. 관리자도 미배정 프로젝트의 본문과 남의 초안을 조회할 수 없다. | 미구현/미검증 |
| R24 | 로그인 상태에서 다른 제공자를 연결하면 두 로그인 수단이 같은 승인 상태·프로젝트·받은함을 사용한다. 이메일 일치에 따른 자동 병합이나 다른 회원의 제공자 계정 덮어쓰기는 발생하지 않는다. | 미구현/미검증 |
| R25 | 컨테이너를 교체해도 DB·첨부 데이터가 남으며, 하루 1회 외부 백업과 7일 보관 정책을 적용한다. 별도 환경에서 DB·첨부를 복구해 참조 정합성과 권한 있는 다운로드를 확인한다. | 미구현/미검증 |
