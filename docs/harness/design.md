# 프로젝트 Agent Harness 설계안

상태: 승인된 설계 · Harness 구현 기준

## 목적

본 웹서비스를 개발하는 Codex가 제품 명세를 찾고, 작업 범위를 정하고, 변경을 검증하고, 다음 작업에 정확한 상태를 전달하도록 개발 환경을 구성한다. 제품에 들어갈 Codex 연동 기능과는 별개의 개발 기반이다.

제품 원본은 [제품 명세 v1.2](../product/spec.md)다. 기술 스택은 [기술 설계](../product/technical-design.md)에 확정돼 있으며 앱 코드는 아직 없다. 애플리케이션이 테스트를 통과했다거나 연동이 동작한다고 가정하지 않는다.

## 선택지

1. AGENTS.md만 작성: 가장 작지만 검증과 재개 규칙이 사람의 기억에 의존한다.
2. 프로젝트 지침 + 작업 절차 + 실행 가능한 점검: 이번 권장안. 제품 코드 없이도 문서 연결과 작업 준비 상태를 검증할 수 있다.
3. 자체 다중 에이전트 실행 플랫폼: 자동 배정·스케줄링까지 포함하므로 현재 팀의 개발 준비 범위를 넘는다. 첫 Harness에서 제외한다.

## 구성

| 예정 파일 | 역할 |
|---|---|
| AGENTS.md | 짧은 시작 지침, 명세 위치, 작업 순서, 핵심 금지사항, 검증 명령 |
| docs/harness/workflow.md | 시작·계획·구현·검증·리뷰·종료·재개 절차 |
| docs/harness/checks.md | 권한·버전·상태 경합·중복 전송·개인 상태 검증 기준과 명세 항목 연결 |
| docs/harness/task-template.md | 범위, 수용 조건, 변경 파일, 실행 증거, 남은 작업 양식 |
| docs/harness/decisions.md | 프로젝트 전체에 유지해야 할 결정과 미결정 사항만 기록 |
| docs/product/technical-design.md | 확정된 스택·회원 정책·운영 조건과 남은 기술 결정 |
| scripts/check-harness.ps1 | 필수 파일·문서 링크·검증 설정·제외 규칙을 검사하는 진입 명령 |
| .gitignore | work/ 등 임시 작업 기록과 로컬 비밀정보를 버전 관리에서 제외 |
| README.md | 팀원이 설치·시작·점검·재개하는 방법 |

제품 명세는 기존 파일을 계속 원본으로 사용한다. 대체본을 복제하지 않는다. 위 파일 이름은 프로젝트 내부 규약이며 AGENTS.md를 제외한 문서가 Codex에 자동 로드된다고 가정하지 않는다. AGENTS.md에서 필요한 문서를 읽도록 안내한다.

## 핵심 지침

- 작업 전 원본 명세와 관련 코드, 현재 변경 사항을 확인한다.
- 확인되지 않은 기술 스택·API·테스트 명령을 사실처럼 적지 않는다.
- 제품 불변 조건: 프로젝트 권한 경계, 초안 비공개, 버전별 동의, 기존 확정본 유지, 사람 승인과 에이전트 조회 분리.
- 서비스의 확인·동의를 개발 에이전트가 대신 수행하지 않는다.
- 기능 변경은 해당 수용 기준에 연결하고 실제 검증 결과를 남긴다. 검증하지 못한 부분은 미검증으로 표시한다.
- 리뷰 지적은 재현 조건과 명세를 확인해 반영한다. 에이전트가 명세를 몰래 변경해 실패를 숨기지 않는다.
- 관련 없는 사용자 변경을 덮어쓰지 않는다. Git 미설정 상태에서는 커밋·브랜치·PR이 존재한다고 가정하지 않는다.
- 모델·전역 Codex 설정·사용자 설치 플러그인은 변경하지 않는다. 역할 설명을 실제 병렬 에이전트 실행으로 간주하지 않는다.

## 작업 및 기록

시작 → 관련 요구사항 확인 → 범위와 수용 조건 정리 → 구현 → 해당 검증 실행 → 필요한 리뷰 → 결과 보고 순서다.

일회성 초안·로그·재개 메모는 work/<task-id>/ 아래 둔다. 루트에 HANDOFF_final_2.md 같은 파일을 계속 만들지 않는다. 같은 작업의 재개 메모는 고정 이름으로 갱신하고 완료 후 남길 가치가 있는 결정만 문서에 반영한다.

work/는 Git에 올리지 않으므로 다른 팀원 PC에 자동 전달되지 않는다. 팀 간 개발 작업의 전달은 공용 작업 기록이나 명시적으로 공유한 산출물을 사용해야 한다. 아직 만들지 않은 제품을 이미 인수인계 서버로 사용할 수 있다고 가정하지 않는다.

완료 보고에는 변경 내용, 검증 명령·결과, 미검증 사항, 다음 작업을 포함한다. 로그나 토큰·비밀값은 통째로 공유하지 않는다.

## 점검 명령의 범위

초기 검사기는 Harness 파일과 로컬 문서 참조가 존재하는지, 제품 명세 경로가 정확한지, 임시 기록 제외 규칙이 있는지를 점검한다. 경로는 실행 위치가 아닌 프로젝트 루트를 기준으로 계산한다.

Harness 점검과 제품 검증 결과는 분리한다. 기술 스택은 정해졌지만 제품 코드와 테스트 실행기가 없는 현재는 제품 검증을 ‘미설정’으로 출력한다. 제품 검증을 요구하는 모드에서는 미설정·명령 실패가 있으면 실패 종료한다. 단순히 문서가 있다는 이유로 제품 테스트 통과를 보고하지 않는다.

앱 구성 단계에서 실제 설치·정적 검사·도메인 테스트·통합 테스트 명령을 등록한다. 임의의 npm 명령이나 가짜 테스트를 지금 만들지 않는다.

## Harness 자체 검증

1. 정상 구성에서 모든 필수 문서 연결이 유효하다.
2. 격리된 임시 복사본에서 필수 문서를 제거하면 검사기가 실패한다.
3. 잘못된 로컬 문서 경로를 넣으면 실패한다.
4. 제품 검증 미설정 상태를 성공으로 숨기지 않는다.
5. 작업 폴더를 바꿔 실행해도 프로젝트 루트를 올바르게 찾는다.
6. 새 Codex 작업에서 실제 로드된 지침 확인은 별도 수동 검증으로 남긴다. 현재 작업에서 파일을 직접 읽은 것은 자동 로드 검증이 아니다.

## 범위와 다음 단계

첫 구현은 위 개발 지침·점검 도구·사용법에 한정한다. 앱 코드, MCP 서버, Discord 연결, 배포, 다중 에이전트 오케스트레이터를 만들지 않는다. Git 저장소 초기화와 기술 스택 결정도 이번 설계의 자동 실행 항목이 아니다.

이 설계 검토 후 파일별 구현·검증 계획을 작성하고 해당 계획에 따라 구축한다.

## 근거

Codex의 AGENTS.md 프로젝트 지침 기능은 공식 문서를 기준으로 한다: https://learn.chatgpt.com/docs/agent-configuration/agents-md

AGENTS.md는 에이전트 지침이며 권한 격리나 테스트 실행을 강제하는 보안 장치가 아니다. 검사기와 향후 CI가 검증을 담당하고, 제품 권한은 서비스에서 집행한다.
